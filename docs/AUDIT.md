# Trace engineering audit

This checklist compares the current implementation with the master specification. The priority order was data integrity and access control, then the screenshot-to-Jira path, then drawing, operator feedback, and test coverage.

| Priority | Surface                                                | Finding and disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0       | Jira create resolver, draft editor, canvas persistence | The resolver accepted an arbitrary client draft and the browser removed it before a durable link was confirmed. Creation now requires an owned workspace and its saved revision and draft ID. The UI saves the reviewed draft before posting. The resolver writes a receipt keyed to the account, workspace and draft. A reload can restore the link from the receipt and the canvas save commits the reference and draft removal together.                                                  |
| P0       | Duplicate creation and requests with unknown outcome   | A lost response could leave an unrecoverable lock. The new create POST sets an indexed Jira issue property. A repeat confirmation after an ambiguous result searches for and verifies the property under the caller's access. It never repeats that POST. Previous-version receipts still prevent resubmission.                                                                                                                                                                              |
| P0       | Forge asset access and storage                         | Uploads could accumulate permanently before a board was saved. Staging has an owner cap and one-hour expiry. Publishing checks file identity and SHA-256 integrity. Files are read through an owned, published board association, and a successful scene save reclaims removed images. Legacy orphaned chunks from interrupted saves are removed when their workspace is deleted. Storage cleanup is best-effort after a committed revision.                                                 |
| P0       | Forge, Convex and offline trust boundaries             | Forge derives ownership from the authenticated resolver context and uses user-scoped product calls. Convex is a single-operator development backend with a server-held relay secret and same-origin loopback checks. The demo uses browser IndexedDB. Neither standalone mode calls Jira or claims to create real issues.                                                                                                                                                                    |
| P1       | Draft generation, editing, import and duplication      | Regeneration overwrote earlier drafts. It now preserves edited drafts and prevents duplicate drafts for the same origins and format. Unsubmitted drafts can be discarded with confirmation. Imports and copies get independent draft IDs and do not copy attempted submissions.                                                                                                                                                                                                              |
| P1       | Screenshot upload, paste, drop, crop and OCR           | Upload validation and asset limits are enforced. An upload failure cannot display crop success. Screenshot region coordinates are preserved relative to the image for later OCR. OCR and crop account for native image cropping and flipping. Rotated images must be reset before rectangle-based OCR or crop. OCR uses bundled English data and real local recognition.                                                                                                                     |
| P1       | Context Magnet, explanation and visual linking         | The demo queries fixture data through the same deterministic ranking pipeline. Deleted pins and references are excluded from analysis. Graph relationships retain explicit evidence in search. Canvas links now bind to both elements and existing cards can link to additional selections. Reference removal records native scene deletion so canvas undo can restore the card.                                                                                                             |
| P1       | Issue types, permissions and evidence                  | The selected issue type's create fields are checked separately rather than issuing a request for every type. The create resolver rechecks the chosen type and its fields and sends ADF. Jira enforces product permissions. The resolver rechecks source access before adding links and adds the Trace workspace and annotation IDs. An explicitly selected full screenshot is uploaded separately using the user's Jira permissions. An upload failure cannot undo or repeat issue creation. |
| P1       | Autosave, dashboard and recovery                       | Draft recovery checkpoints run independently of the network debounce in the standalone modes. A checkpoint from an older revision can be recovered as a separate copy. Production does not put customer canvas data into browser crash-recovery storage.                                                                                                                                                                                                                                     |
| P2       | Pages, buttons and keyboard                            | Audited workspace search, favorite filters, templates, create, open, rename, duplicate, delete, import, settings, command palette and theme controls. The editor's selection, hand, free draw, shapes, text, line, arrow, eraser, sticky, preview, fit and zoom tools use Excalidraw. Drawing and upload tools are disabled while the canvas is initializing. Inspector tabs support arrow keys, Home and End. Modal creation shows the reviewed title, type and project before any write.   |
| P2       | Build and performance                                  | Verified strict TypeScript and both frontend targets. Kept incremental scene saves, bounded images, source result limits, separate Forge assets and local OCR on demand. Metadata validation now fetches fields for one selected issue type. Very large Excalidraw dependency chunks and the current per-workspace storage limits remain visible tradeoffs.                                                                                                                                  |
| P2       | Atlassian integration verification                     | Jira search, metadata, creation, attachment and receipt contracts have local tests with mocked API boundaries. The browser workflow injects an explicitly mocked Forge host and forces a failure after submission. It verifies recovery and persisted reference on reload. Live OAuth scopes, Jira issues, attachment transport, Confluence, Graph and Rovo/MCP still need a registered app and approved test site.                                                                          |
| P3       | Original specification gaps                            | One canvas per private workspace. Shared boards, real-time multiplayer, general search continuation, semantic embeddings, arbitrary Jira custom field entry, Jira subtask parent selection and Marketplace publication are outside the verified implementation. Forge Rovo and MCP manifest modules still depend on host enablement and availability. User-facing dependency labels distinguish supported paths from deterministic demo fixtures.                                            |

## Repeat the checks

Run `npm run lint`, `npm test`, `npm run build` and `npm run build:forge` from the project folder. Run `npm run test:e2e -- --workers=1` for the standalone canvas workflow. Set `TRACE_TEST_CONVEX=true` after starting the configured local deployment. Set `TRACE_TEST_OCR=true` to exercise the bundled recognizer. Set `TRACE_TEST_FORGE_MOCK=true` to run the screenshot-to-Jira recovery browser test with its test-only adapter. `TRACE_TEST_PORT` lets an existing Vite server keep its port.

Use the [Atlassian installation and verification guide](ATLASSIAN_INTEGRATIONS.md) for the live gate. Validate the receipt workflow and optional attachment against a Jira sandbox project before relying on either in production.
